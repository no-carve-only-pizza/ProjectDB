## 이번 회차 상세 진행 내용

### 1. 회의 목적

이번 회차에는 새로운 기능 구현보다, 3차 보고서까지 진행된 결과물을 바탕으로 남은 작업을 어떻게 나눌지 논의하였다.

현재 프로젝트는 eBPF 기반 EDR Agent, 백엔드 API, 프론트엔드 대시보드가 각각 구현되어 있으며, 3차 보고서에서 대시보드가 백엔드 이벤트를 조회하는 것까지 확인하였다. 따라서 다음 단계의 핵심 목표는 각 파트를 개별 기능으로 두는 것이 아니라, 실제 탐지 이벤트가 웹 화면까지 이어지는 하나의 EDR 시스템으로 검증하는 것이다.

전체 검증 흐름은 다음과 같이 정리하였다.

```text
EDR Agent 이벤트 생성
  -> 백엔드 API 수집 및 저장
  -> 대시보드 이벤트 조회 및 시각화
  -> 공격 시나리오 기반 탐지 결과 확인
```

---

### 2. 역할 분담 논의 결과

회의를 통해 남은 기간의 역할을 다음과 같이 나누었다.

| 담당 | 역할 | 주요 책임 |
|------|------|-----------|
| 박도현 | EDR Agent / 시스템 총괄 | Agent 빌드·실행 안정화, 백엔드 전송 테스트, 이벤트 포맷 확인, 발표용 아키텍처 설명 준비 |
| 강수빈 | 공격 시나리오 / 탐지 검증 | 발표용 공격 시나리오 선별, 각 시나리오별 기대 룰 정리, 탐지 성공표 작성, MITRE ATT&CK 매핑 |
| 이정훈 | 백엔드 / API / 데이터 | 이벤트 수집·저장·조회 API 안정화, NDJSON 수집 API 검증, Swagger 최신화, 프론트엔드 응답 형식 조율 |
| 장수연 | 프론트엔드 / 대시보드 UX | 이벤트 목록 UI 개선, severity·rule_id 필터, alert summary 카드, 이벤트 상세 화면 구성 |

이 분담은 다음과 같은 흐름을 기준으로 한다.

```text
박도현: Agent 이벤트 생성
      ↓
이정훈: Backend 수집·저장·조회
      ↓
장수연: Dashboard 시각화
      ↑
강수빈: 공격 시나리오로 전체 흐름 검증
```

---

### 3. 발표용 데모 방향

회의에서는 모든 탐지 룰을 하나씩 보여주는 방식보다, EDR 제품의 동작 방식이 잘 드러나는 대표 공격 체인을 중심으로 시연하는 것이 효과적이라고 판단하였다.

발표용 대표 흐름은 다음과 같이 정리하였다.

```text
1. /tmp 경로에서 드로퍼 실행
2. 비표준 포트로 아웃바운드 연결 발생
3. 상관분석 룰 R-020 발화
4. 웹 대시보드에서 critical alert 확인
5. 가능할 경우 active response kill 기능을 보너스 시연
```

이 흐름은 단일 이벤트 탐지뿐 아니라, `/tmp 실행 -> 네트워크 연결 -> 상관분석 alert`로 이어지는 다단계 탐지 구조를 보여줄 수 있어 발표 설득력이 높다고 판단하였다.

---

### 4. 대시보드 개선 논의

3차 보고서에서는 이벤트 목록 렌더링까지 확인하였다. 이번 회의에서는 최종 발표 전까지 대시보드에 추가하면 좋은 항목을 정리하였다.

| 항목 | 목적 |
|------|------|
| severity 필터 | critical/high 이벤트를 빠르게 확인 |
| rule_id 필터 | 특정 탐지 룰 기준으로 이벤트 확인 |
| alert summary 카드 | 전체 위험도와 알림 수를 한눈에 표시 |
| 이벤트 상세 모달 | PID, 프로세스명, 경로, 목적지 IP, alerts 등 상세 정보 확인 |
| 최근 critical alert 목록 | 발표 및 운영 관점에서 중요한 이벤트 강조 |
| event type별 카운트 | exec/file/network/dns 등 이벤트 분포 확인 |
| agent 상태 표시 | 백엔드뿐 아니라 에이전트 동작 상태까지 표현 |

이 항목들은 필수 구현 사항이라기보다, 프로젝트를 단순 로그 뷰어가 아닌 EDR 대시보드처럼 보이게 만드는 개선 방향으로 정리하였다.

---

### 5. 최종 산출물 보강 방향

우수 프로젝트 발표 가능성을 고려하여, 기능 구현 외에도 프로젝트의 완성도를 설명할 수 있는 산출물을 준비하기로 하였다.

| 산출물 | 내용 |
|--------|------|
| MITRE ATT&CK 매핑 표 | 각 탐지 룰을 Linux ATT&CK technique과 연결 |
| 공격 시나리오별 탐지 성공표 | 시나리오, 기대 룰, 실제 탐지 여부, 대시보드 표시 여부 정리 |
| 전체 아키텍처 다이어그램 | Agent, Backend, Dashboard, 공격 시나리오의 연결 구조 표현 |
| 발표용 데모 순서 | 실제 시연 중 사용할 명령어와 확인 화면 순서 정리 |

## 이슈 및 해결 방안

| 이슈 | 해결 방법 |
|------|----------|
| 각 파트는 구현되어 있으나 전체 파이프라인 검증이 아직 충분하지 않음 | 다음 회차에서 Agent -> Backend -> Dashboard 흐름을 실제 이벤트로 검증 |
| 발표에서 모든 룰을 설명하면 내용이 산만해질 수 있음 | 대표 공격 체인 중심으로 데모를 구성하고, 나머지 룰은 표로 정리 |
| 대시보드가 단순 이벤트 목록으로 보일 수 있음 | severity 필터, alert summary, 상세 모달 등 EDR 콘솔에 가까운 기능을 우선 검토 |
| 최종 결과물의 보안적 의미를 설명할 자료가 필요함 | MITRE ATT&CK 매핑과 탐지 성공표를 별도 산출물로 준비 |
